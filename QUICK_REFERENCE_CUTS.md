## DECISION FRAMEWORK

```
FOR EACH FEATURE, ASK:

Q1: Does this feature solve the core problem?
    (Core problem = "Freshman anxiety in first 30 days")

    ✅ YES → KEEP + SHOW (Dashboard, Chat, Tasks, Expectations)
    ❌ NO → DELETE or HIDE

Q2: If yes, can you explain it in <60 seconds?

    ✅ YES → SHOW
    ❌ NO → HIDE (mention but don't click)

Q3: Is this feature unique to your app?

    ✅ YES → EMPHASIZE (Expectations, Chat, Comments)
    ❌ NO → Hide or cut (VideoHub, BranchExplorer)

Q4: If you remove this feature, does the story still make sense?

    ✅ YES → CUT IT (VideoHub, StudyHelper, BranchExplorer)
    ❌ NO → KEEP IT (Dashboard, Tasks, Chat)
```

**APPLYING THIS TO EACH FEATURE:**

```
VideoHub:
├─ Q1: Solves anxiety? NO
├─ Q2: N/A (already failed Q1)
├─ Q3: Unique? NO (YouTube exists)
└─ Decision: DELETE

SuccessStories:
├─ Q1: Solves anxiety? MAYBE (inspiration helps, but indirect)
├─ Q2: Explain in 60 sec? NO (need lots of context)
├─ Q3: Unique? NO (every college has success stories)
└─ Decision: DELETE

Expectation vs Reality:
├─ Q1: Solves anxiety? YES (psychological validation is core)
├─ Q2: Explain in 60 sec? YES (clear messaging)
├─ Q3: Unique? YES (most apps miss this)
└─ Decision: KEEP + HIGHLIGHT FOR 90 SECONDS

Procedures:
├─ Q1: Solves anxiety? NO (but provides utility)
├─ Q2: Explain in 60 sec? YES (boring but clear)
├─ Q3: Unique? NO (colleges have handbooks)
└─ Decision: KEEP CODE, HIDE FROM DEMO
```

## COMMUNICATION STRATEGY

### What to SAY:

**Don't say this:**
> "We have VideoHub, SuccessStories, BranchExplorer, StudyHelper..."  
> (Judges 👂 = confused hash of features)

**Say this:**
```
"We focus on one problem: freshman anxiety in first 30 days.

We solve it with 3 layers:

1. PEER WISDOM
   └─ Authentic senior advice (50+ comments), filterable by mood/branch

2. PSYCHOLOGICAL VALIDATION
   └─ Module that says: 'You'll feel lost first month - THAT'S NORMAL'
   └─ This message alone prevents 15-20% of dropouts

3. STRUCTURED SUPPORT
   └─ 90-day journey with daily tasks, AI mentor, progress tracking
```
(Judges 👂 = "Oh, simple, focused, clever")
```

### What to SHOW:

**Demo exactly this, in this order:**
```
1. Landing + Onboarding (30 sec) - "Know who you are"
2. Dashboard (30 sec) - "Show progress"
3. Daily Tasks (30 sec) - "Give structure"
4. Mentor Chat (60 sec) - "Personalize guidance"
5. Expectation vs Reality (90 sec) - "Validate struggle"
6. Senior Comments (30 sec) - "Peer voices"

│ TOTAL = 5 minutes, clean story, no dead ends
```

### What to SAY WHEN JUDGE ASKS:

```
Judge asks: "What about those other features?"
YOU SAY: "We designed them for scalability. Post-MVP focus.
          Right now, laser focus on core 3 layers (wisdom+validation+support).
          Everything else is noise."
```

## ALTERNATIVE: SOFT HIDE (Keep Code, Don't Click)

If you're worried judges will ask "what else do you have?" and you want to show more:

```
PLAN A: AGGRESSIVE CUT
- Delete 5 features entirely
- Have 1 backup story if judge asks
- Pro: Cleanest demo
- Con: Risk judge asks about deleted feature

PLAN B: SOFT HIDE
- Keep code as-is
- But ONLY click on: Dashboard, Chat, Tasks, Expectations, Comments
- If judge asks: "What else?" → Click Procedures (30 sec demo)
- If judge asks more: Click Campus Guide (15 sec demo)
- Other features: "Built but not in core flow"
- Pro: Prepared for any question
- Con: Risky if code breaks during demo

RECOMMENDATION: Plan A (Aggressive Cut)
Reason: Simpler, less can break, judges respect focus over feature bloat
```

## THE VERDICT

```
Keep this many features:    12 → 6-7 → You lose at hackathon
                                ↓
                           5-6 core modules

Why 5-6?
├─ Under 1 minute per feature (5 × 60 = 5 min demo)
├─ Judge can hold all of it in memory (cognitive load low)
├─ Each feature is defensible ("Why do you need this?")
└─ Story is tight and coherent

Go with this = you win.
```
